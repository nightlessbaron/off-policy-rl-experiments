# Off-Policy Clip Sweep v3

## Hypothesis

**How does `clip_high` affect training stability and final reward in off-policy asynchronous GRPO at a fixed staleness level?**

In async RL training, rollout samples are generated by a policy that lags behind the training policy. The `clip_high` parameter controls the upper bound of the PPO clipping ratio, limiting how much the policy can change per update. With stale off-policy data, aggressive clipping (low `clip_high`) may be overly conservative, while loose clipping (high `clip_high`) may cause instability.

This study isolates the effect of `clip_high` by fixing all other variables, particularly staleness at 2.4 sync intervals.

## Experimental Setup

### Model
- **Base model**: Qwen2.5-7B-Instruct
- **Algorithm**: GRPO (Group Relative Policy Optimization)
- **Training mode**: Fully asynchronous (detached rollout and training)

### Data
- **Training**: MATH combined (118.2k), filtered to easy problems (pass_rate 0.3-0.6), 50k samples
- **Validation**:
  - MATH combined val (1k, equal distribution across difficulty)
  - AIME 2024 (tagged)
  - AIME 2025 (tagged)

### Hardware
- 1 node, 8 GPUs (H200)
- 4 GPUs for rollout (vLLM, TP=1)
- 4 GPUs for training (FSDP2, SP=4)

### Training Configuration

| Parameter | Value |
|-----------|-------|
| max_prompt_length | 4096 |
| max_response_length | 8192 |
| n_responses_per_prompt | 16 |
| learning_rate | 1e-6 |
| lr_warmup_steps | 10 |
| weight_decay | 0.1 |
| grad_clip | 1.0 |
| loss_agg_mode | token-mean |
| temperature | 1.0 |
| trigger_parameter_sync_step | 4 |
| require_batches | 4 |
| overlong_buffer | enabled (4096 tokens, penalty=1.0) |
| reward_manager | dapo |

### Sweep Dimensions

| Parameter | Values |
|-----------|--------|
| clip_high | 2.0, 2.2, 2.4, 2.6, 2.8 |
| clip_low | 2.0 (fixed) |
| KL (kl_in_reward + kl_loss) | on (coef=0.01) / off |
| staleness_threshold | 2.4 (fixed) |

**Total experiments: 10**

### Experiment Naming Convention

```
offpol-v3-cL{clip_low}-cH{clip_high}-kl-{on|off}-s{staleness}
```

Example: `offpol-v3-cL2.0-cH2.4-kl-on-s2.4`
